# Design one skill

State the job in terms of a useful result and a caller who needs it. Record positive requests, nearby negatives, inputs, output contract, missing-input behavior, relevant dependencies, side effects and observable acceptance conditions. Choose creation or scoped revision and carry forward settled decisions.

Search the need index through the lookup helper. It reads the catalog locally and returns a bounded selection; it does not load the whole research corpus into model context. Start with the smallest fitting set, normally no more than six. Read use/avoid conditions and conflicts, not only the preferred example. Source-inspected means text was studied, not that the behavior ran.

Library examples and source locations have distinct roles. Portable catalog/report checks need the declared repository-relative files. Full raw-source checks need a supplied local map and original bytes; absent raw source is unavailable verification, not a clean pass. Do not infer a revision or replace a missing hash with newer bytes. Historical excluded examples are not active verified references.

Resolve the library from the folder the user's instructions name, an explicit `--library-root`, or this source distribution. Never fall back to a home-directory library that nobody named. A copy without a library must report the missing dependency ("no library found; start one with dissect-this or pass --library-root"). For an original method, a user-approved bounded design can proceed with that limitation; source adaptation needs the relevant source and rights.

Choose a short main file, linked task-specific references, deterministic helpers when needed and concrete assets when needed. Avoid copying a studied framework's lifecycle, global policy, shipping steps or persistent mode. Keep optional guidance conditional. Honor the user's requested names, destinations and stricter project privacy rules.

Before implementation of substantial work, present behavior, file surfaces, checks and an editable flow for the required approval. A small approved revision can use a short plan. Preserve unrelated resources; removing an existing resource needs evidence it belongs to the requested change and current authorization.

The design record should name selected mechanic IDs and reasons, declined conflicts, source/rights limits, and the proposed check. It is a project record, not a second automatic memory store.
